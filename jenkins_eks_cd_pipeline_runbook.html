Module 11 · Kubernetes on AWS EKS

Deploy to EKS from Jenkins Pipeline.

This runbook extends your working Jenkins CI pipeline into a full CD pipeline. Jenkins will build a Java Maven app, push a Docker image, connect to an EKS cluster using AWS CLI + kubectl, and deploy the new image to Kubernetes.

01
Mental model

Architecture Overview

Jenkins does not deploy magically. It simply runs the same commands a DevOps engineer would run manually: AWS CLI creates kubeconfig, then kubectl talks to the EKS API server.

GitHub

Stores the application source code, Jenkinsfile, Dockerfile, and Kubernetes manifest files.

Jenkins

Runs the CI/CD pipeline after GitHub webhook triggers the Multibranch job.

Docker Registry

Stores the built Docker image. You can use Docker Hub first, then AWS ECR later.

Amazon EKS

Runs the Kubernetes cluster. Jenkins deploys to it using kubectl.

03
Cluster setup

Create or Confirm the EKS Cluster

If you already have an EKS cluster, verify it. If not, create one with eksctl or AWS Console. For learning, eksctl is the fastest path.

Create simple EKS cluster with eksctl
eksctl create cluster \
  --name jenkins-eks-demo \
  --region eu-central-1 \
  --nodegroup-name demo-nodes \
  --node-type t3.medium \
  --nodes 2 \
  --nodes-min 1 \
  --nodes-max 3 \
  --managed
Verify cluster locally
aws eks update-kubeconfig --region eu-central-1 --name jenkins-eks-demo
kubectl get nodes
kubectl get pods -A
Important: if kubectl get nodes does not work manually, it will not work in Jenkins. Fix cluster access first.
04
Authentication and authorization

Give Jenkins AWS and EKS Access

Jenkins needs AWS permissions to describe the EKS cluster and to push images if you use ECR. It also needs Kubernetes access inside the EKS cluster.

Recommended demo IAM user

Create an IAM user or role named something like jenkins-deployer. For a learning demo, you can use broader permissions, then reduce them later.

AWS permissions

Minimum for kubeconfig: eks:DescribeCluster. For ECR option, also add ECR push permissions.

EKS access

Modern EKS access should use EKS access entries, not the old aws-auth ConfigMap.

Production note

For production, avoid cluster admin. Use namespace-level RBAC and least privilege.

Create EKS access entry for Jenkins IAM principal

Replace the ARN, cluster name, and region with your real values.

Create access entry
aws eks create-access-entry \
  --cluster-name jenkins-eks-demo \
  --principal-arn arn:aws:iam::123456789012:user/jenkins-deployer \
  --region eu-central-1
Associate cluster admin policy for demo
aws eks associate-access-policy \
  --cluster-name jenkins-eks-demo \
  --principal-arn arn:aws:iam::123456789012:user/jenkins-deployer \
  --policy-arn arn:aws:eks::aws:cluster-access-policy/AmazonEKSClusterAdminPolicy \
  --access-scope type=cluster \
  --region eu-central-1
Learning vs production: Cluster admin is okay for a demo. For real company work, create limited namespace access.
05
Jenkins server tools

Install kubectl and AWS CLI Inside Jenkins Container

The Jenkinsfile will run aws and kubectl. That means both tools must exist inside the Jenkins container.

Enter Jenkins container as root
docker exec -it -u 0 jenkins bash
Install packages
apt update
apt install -y curl unzip ca-certificates
Install AWS CLI v2
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
unzip awscliv2.zip
./aws/install
aws --version
Install kubectl
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl
kubectl version --client
Rule: if a command appears in the Jenkinsfile, the Jenkins runtime must have that command installed.

Manual EKS Connection Test from Jenkins Container

Before adding a deploy stage, prove that Jenkins can talk to EKS. This saves hours of debugging.

For safety, do this using Jenkins credentials in a temporary test pipeline if possible. For a quick learning test, you can enter the container and export credentials temporarily, then remove shell history if needed.

Temporary manual test pattern
export AWS_ACCESS_KEY_ID="YOUR_ACCESS_KEY"

Create Kubernetes Manifests

These are the minimum Kubernetes files needed for this demo: Namespace, Deployment, and Service.

k8s/namespace.yaml

namespace.yaml
apiVersion: v1
kind: Namespace
metadata:
  name: demo-app

k8s/deployment.yaml

The image value is only a starting value. Jenkins will replace it during deployment using kubectl set image.

deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: java-maven-app
  namespace: demo-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: java-maven-app
  template:
    metadata:
      labels:
        app: java-maven-app
    spec:
      containers:
      - name: java-maven-app
        image: mujuules01/demo-app:latest
        ports:
        - containerPort: 8080

k8s/service.yaml

service.yaml
apiVersion: v1
kind: Service
metadata:
  name: java-maven-app-service
  namespace: demo-app
spec:
  type: LoadBalancer
  selector:
    app: java-maven-app
  ports:
  - protocol: TCP
    port: 80
    targetPort: 8080
Check your app port: if your Java app runs on a different port, change containerPort and targetPort.

Only if Docker Hub repo is private

Create Kubernetes Image Pull Secret

If your Docker Hub repository is private, Kubernetes needs credentials to pull the image. If the repo is public, skip this section.

Create Docker Hub image pull secret
kubectl create secret docker-registry dockerhub-secret \
  --docker-username=YOUR_DOCKERHUB_USERNAME \
  --docker-password=YOUR_DOCKERHUB_TOKEN \
  --docker-email=YOUR_EMAIL \
  -n demo-app

If using a private repo, add this under spec.template.spec in your Deployment:

imagePullSecrets snippet
imagePullSecrets:
- name: dockerhub-secret
11
MVP pipeline

Jenkinsfile · Docker Hub to EKS

This version keeps your current Docker Hub workflow and adds a deploy stage to EKS.

Jenkinsfile with EKS deploy stage
#!/usr/bin/env groovy

pipeline {
    agent any

    tools {
        maven 'maven-3.9'
    }

    environment {
        DOCKER_REPO = 'mujuules01/demo-app'
        GITHUB_REPO = 'java-maven-app-master-EKS'
        GITHUB_REPO_OWNER = 'mjulestek'
        GIT_BRANCH_TO_PUSH = 'jenkins-jobs'

        AWS_REGION = 'eu-central-1'
        EKS_CLUSTER_NAME = 'jenkins-eks-demo'
        K8S_NAMESPACE = 'demo-app'
        K8S_DEPLOYMENT = 'java-maven-app'
        K8S_CONTAINER = 'java-maven-app'
    }

    stages {
        stage('increment version') {
            steps {
                script {
                    echo 'incrementing the version...'
                    sh 'mvn build-helper:parse-version versions:set -DnewVersion=\\${parsedVersion.majorVersion}.\\${parsedVersion.minorVersion}.\\${parsedVersion.nextIncrementalVersion} versions:commit'

                    env.IMAGE_TAG = sh(script: 'mvn help:evaluate -Dexpression=project.version -q -DforceStdout', returnStdout: true).trim()
                    env.DOCKER_IMAGE = "${DOCKER_REPO}:${IMAGE_TAG}"

                    echo "New app version is: ${IMAGE_TAG}"
                    echo "Docker image will be: ${DOCKER_IMAGE}"
                }
            }
        }

        stage('build app') {
            steps {
                script {
                    echo 'building the application...'
                    sh 'mvn package'
                }
            }
        }

        stage('build image') {
            steps {
                script {
                    echo 'building the docker image...'
                    withCredentials([usernamePassword(credentialsId: 'docker-hub-repo', passwordVariable: 'DOCKER_PASS', usernameVariable: 'DOCKER_USER')]) {
                        sh 'docker build -t $DOCKER_IMAGE .'
                        sh 'echo $DOCKER_PASS | docker login -u $DOCKER_USER --password-stdin'
                        sh 'docker push $DOCKER_IMAGE'
                    }
                }
            }
        }

        stage('deploy to EKS') {
            steps {
                script {
                    echo 'deploying application to EKS...'
                    withCredentials([usernamePassword(credentialsId: 'aws-credentials', passwordVariable: 'AWS_SECRET_ACCESS_KEY', usernameVariable: 'AWS_ACCESS_KEY_ID')]) {
                        sh 'aws sts get-caller-identity'
                        sh 'aws eks update-kubeconfig --region $AWS_REGION --name $EKS_CLUSTER_NAME --kubeconfig kubeconfig'
                        sh 'KUBECONFIG=kubeconfig kubectl get nodes'
                        sh 'KUBECONFIG=kubeconfig kubectl apply -f k8s/namespace.yaml'
                        sh 'KUBECONFIG=kubeconfig kubectl apply -f k8s/'
                        sh 'KUBECONFIG=kubeconfig kubectl set image deployment/$K8S_DEPLOYMENT $K8S_CONTAINER=$DOCKER_IMAGE -n $K8S_NAMESPACE'
                        sh 'KUBECONFIG=kubeconfig kubectl rollout status deployment/$K8S_DEPLOYMENT -n $K8S_NAMESPACE'
                    }
                }
            }
        }

        stage('commit version update to git repo') {
            steps {
                script {
                    echo 'commit version update to git repo...'
                    withCredentials([usernamePassword(credentialsId: 'github-credentials', passwordVariable: 'GITHUB_TOKEN', usernameVariable: 'GITHUB_USER')]) {
                        sh 'git config --global user.email "jenkins@example.com"'
                        sh 'git config --global user.name "jenkins"'

                        sh 'git status'
                        sh 'git branch'

                        sh 'git remote set-url origin https://$GITHUB_USER:$GITHUB_TOKEN@github.com/$GITHUB_REPO_OWNER/$GITHUB_REPO.git'
                        sh 'git remote -v'

                        sh 'git add .'
                        sh 'git commit -m "jenkins increment version [skip ci]" || true'
                        sh 'git push origin HEAD:$GIT_BRANCH_TO_PUSH'
                    }
                }
            }
        }
    }
}
12
More AWS-native option

Optional: Use AWS ECR Instead of Docker Hub

ECR is the more AWS-native registry for EKS. Use this after your Docker Hub version works.

Create ECR repository

Create ECR repo
aws ecr create-repository \
  --repository-name demo-app \
  --region eu-central-1

ECR Jenkinsfile idea

Replace the Docker Hub login/push with AWS ECR login/push.

ECR build image stage pattern
environment {
    AWS_REGION = 'eu-central-1'
    AWS_ACCOUNT_ID = '123456789012'
    ECR_REPO = 'demo-app'
    ECR_REGISTRY = "${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com"
}

stage('build and push image to ECR') {
    steps {
        script {
            env.DOCKER_IMAGE = "${ECR_REGISTRY}/${ECR_REPO}:${IMAGE_TAG}"

            withCredentials([usernamePassword(credentialsId: 'aws-credentials', passwordVariable: 'AWS_SECRET_ACCESS_KEY', usernameVariable: 'AWS_ACCESS_KEY_ID')]) {
                sh 'aws ecr get-login-password --region $AWS_REGION | docker login --username AWS --password-stdin $ECR_REGISTRY'
                sh 'docker build -t $DOCKER_IMAGE .'
                sh 'docker push $DOCKER_IMAGE'
            }
        }
    }
}
ECR pull rule: EKS worker nodes need permission to pull from ECR. Managed node groups commonly have this, but verify the node IAM role has ECR read permissions.

15
Fix fast

Troubleshooting

Most failures happen in authentication, image pull, or mismatched deployment/container names.

aws command not found

AWS CLI is not installed inside Jenkins container.

Check
docker exec -it -u 0 jenkins bash
aws --version

kubectl command not found

kubectl is not installed inside Jenkins container.

Check
kubectl version --client

Unauthorized from kubectl

Jenkins AWS identity can describe the cluster but is not authorized inside Kubernetes. Configure EKS access entry.

ImagePullBackOff

Kubernetes cannot pull the image. Check image name, tag, registry credentials, Docker Hub private secret, or ECR node role permissions.

Deployment not found

Your K8S_DEPLOYMENT value does not match the Deployment metadata name.

Container not found

Your K8S_CONTAINER value does not match the container name inside deployment.yaml.

17
Senior rules

Final Rules of Thumb

These rules make the setup easier to debug and explain.

First make deployment work manually with kubectl, then automate it in Jenkins.
If Jenkinsfile uses a command, install that command inside Jenkins container.
Use AWS CLI to generate kubeconfig dynamically during the pipeline.
Do not store kubeconfig or AWS secrets directly in GitHub.
Make Maven version, Docker tag, and Kubernetes deployed image match.
Use Docker Hub first for learning, then move to ECR for AWS-native deployment.
When using ECR, verify EKS node IAM role can pull images.
Use rollout status as the pipeline gate before calling deployment successful.
Use [skip ci] or Ignore Committer Strategy to avoid Jenkins commit loops.
Final demo architecture:
GitHub → Jenkins Multibranch Pipeline → Docker Registry → AWS EKS → Kubernetes Deployment Rollout
